# X Capture Studio 1.0.0-rc.7 · 安装与使用

这是重新从实际保留的 rc.6 源码完成构建的多媒体候选版；不是此前不存在的 rc.7 链接。GitHub main 和已脱敏历史未修改。

## 电脑端：Chrome / Edge

1. 解压 `x-capture-rc7-chrome.zip` 到稳定目录。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式。
3. 停用旧版，加载直接包含 manifest.json 的目录；已有固定安装目录也可先备份，再替换并重新加载。
4. 完整刷新 X 的帖子或 Article 页面。不要同时启用两份 X Capture。

无需 Node.js 或自行编译安装包。浏览器的扩展权限确认仍由用户完成。

## 手机端：iPhone / iPad Safari + Stay

1. 解压 `x-capture-rc7-stay.zip`，找到 `x-capture-rc7-stay.user.js`。
2. 在 Stay 的资料库中停用旧脚本，从本地文件导入新脚本并启用。
3. 确认 Safari 的 Stay 扩展被允许访问当前 X 网站，回到 Safari 完整刷新 X 页面。
4. 点击帖子相机按钮或右下方 X Capture。脚本不运行在 X 原生 App 中。

## 新增能力在哪里

进入工作台「文本」页签，展开「媒体资源与高清检查」。打开工作台/准备复制时会进行有限资源检查；可以重新检查，也可以停止。检查期间仍可查看和选择帖子。复制、TXT、Markdown 和 Copy for AI 共用相同媒体数据与选区。

- 图片优先查找可用高清候选。orig 不可用时降级；全部验证受限时保留页面已有地址，不把失败的候选拼接地址冒充可用原图。
- MP4、HLS/M3U8、DASH/MPD 可以同时保留。默认输出推荐资源和播放页；「全部资源」可查看已发现的其他画质、音轨与字幕。
- 支持轻量 HLS/DASH/VMAP 资源解析，区分播放清单、文件、分片、封面与播放器页面。没有发现的格式不会编造。
- HTML track、页面数据、HLS、DASH 的字幕/音轨按所属视频列出；无独立文件的内嵌字幕会明确标记。
- 默认仍是「媒体标注 + 链接」，媒体留在原文位置；Markdown 图片嵌入语法是可选项。
- 默认不分享签名/令牌链接；临时允许需要明确确认，授权不跨会话持久保存。匿名仍隐藏自动附加的媒体及来源回链。

## 验证等级与限制

216 项单元/契约检查与 243 项本地浏览器/文件回读检查通过。浏览器用 Playwright Chromium、合成 DOM/资源、记录式 GM/剪贴板适配器，不代表真实 iOS/Stay。实际 MV3 新配置文件启动未等到 service worker，已标为 BLOCKED。没有验证实时 X 的所有页面变体或每条媒体资源在真实用户环境中的可获取率。

Stay 新资源检查使用受限 native fetch，不依赖未验证的 GM 重定向控制；CORS 不允许时保留已观察到的资源，不冒称验证成功。不会下载视频分片、密钥或绕过 DRM。第三方外部媒体可以保留观察到的链接，但默认不进行跨域主动抓取。

不捆绑字体文件。已有 PDF 字体准备/合法本地导入规则不变。本次不包含字幕语音识别、完整视频下载、字幕格式转换。

## 回退

保留原 rc.6/rc.5 安装目录或旧 Stay 脚本。出现问题先停用 rc.7，再启用旧版并刷新页面。不要同时运行两个版本。此候选版不改写用户原帖内容，不要求修改账户设置或导出 Cookie。

## 源码

`x-capture-rc7-source.zip` 提供当前源码、独立测试、依赖许可、更新补丁及预期文件 SHA。正常开发：`npm install`、`npm run typecheck`、`npm run build`、`npm test`。

源码中的 GitHub 安装教程/历史 releases 仍指向公开 rc.5；不要将其误认为 rc.7 已经发布。本次可安装文件是本交付包中的 rc.7 ZIP/user.js。
